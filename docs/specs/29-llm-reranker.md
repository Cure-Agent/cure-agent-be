# 29. LLM 리랭커 — K=30 확장·재정렬·관련도 게이트

> **이 문서는 작성 시점의 작업 지시다 — 현재 시스템 상태가 아니다.**

## 목표

§27 판정표의 나머지 발동 항목을 실행한다. 기준선의 실패는 순서 문제였다 — Recall@30(0.983) ≫
Recall@5(0.780), 실패 13건 중 12건이 6~20위. 코사인 유사도는 「어떤 단어를 썼는가」에
끌려가 여러 지침이 공유하는 어휘(한약·처방·침 치료)가 병명 신호를 희석시킨다. 검색을 K=30으로
열고 LLM이 「이 근거가 이 질문에 답하는가」로 재정렬해 상위 5개를 고르게 한다. 동시에 §28
거리 컷의 잔여 40%(표현 민감성)를 관련도 점수 게이트로 메운다.

## 실측 조사 (2026-08-01, 프로덕션 코퍼스 7,154청크 × 평가셋 74문항)

gpt-5.4-mini 리스트와이즈 재정렬(K=30 후보 → 상위 5 + top-1 관련도 0~10)을 전 문항에 실행했다.

| 확인 항목 | 실측 |
|---|---|
| **Recall@5** | 0.780 → **0.983** — 진단 상한(Recall@30)에 도달했다. 기존 실패 13건 중 12건 회수(9→1위, 20→1위, 19→1위 등), 잔여 1건은 애초에 top-30 밖(058, 나열식 질문) |
| **MRR@5 / Recall@1** | 0.676 → **0.932** / 0.610 → **0.898** — 정답이 거의 항상 1위로 온다 |
| **악화 0건** | 기존 top-5 정답이 리랭크로 탈락한 사례가 없다 |
| **관련도 점수 분리** | answerable 59건: 57건이 9~10, min 8. abstain 15건: 12건이 ≤4, 8점 3건 |
| **8점 abstain 3건의 정체** | 임신 질출혈·임신 요로감염·다발성경화증 — **전부 §28 거리 컷(0.42)이 이미 차단하는 문항**이다(거리 0.427~0.516). 반대로 거리 컷이 놓치던 6건(충수염·이명·녹내장 등 어휘 중첩형)은 전부 점수 ≤4 — **두 게이트는 상호보완**이다 |
| 이중 게이트 합산 | 거리 컷(§28) + 점수 컷 6 기준: **기권 재현 15/15(100%), 정답 손실 0** (§28 단독은 9/15였다) |
| 지연 | 리랭크 호출 p50 **958ms** · p90 1,286ms · max 2,161ms — TTFT에 약 1초가 더해진다 |
| 비용 | 질의당 호출 1회, 입력 ~10k 토큰(후보 30개 × 300자 발췌) ≈ $0.002 |
| 파싱 실패 | 74문항 중 0건 (`response_format: json_object`) |

### LLM 리랭커를 채택한다 (2026-08-01 사용자 확정)

전용 크로스인코더(Cohere Rerank 등)는 지연(~200ms)이 더 짧지만, **품질 상한은 LLM 리랭커가
이미 도달했다** — 더 올라갈 여지가 없으니 외부 벤더의 이득은 지연뿐이고, 그 대가로 API 키·과금
계정·장애 도메인이 하나 늘어난다. 기존 OpenAI 키·기존 4단 방어 체계(§11) 아래에서 동작하는
쪽을 택한다. 지연 p50 +1초는 수용한다 — 스트리밍 답변 전체가 수십 초이고, `retrieval.started`
이벤트가 이미 진행 상태를 보여준다.

### 게이트는 3단이 된다 — 각자 다른 실패를 잡는다

```
검색 K=30 → ① 거리 게이트(§28, top-1 > 0.42 기권) → ② LLM 재정렬(30→5) → ③ 점수 게이트(top-1 관련도 < 6 기권)
```

- ①은 **확실히 먼** 질문을 리랭크 비용 없이 자른다(추상 표현·짧은 질문에 강함 — §28 실측의
  표현 민감성 발견 그대로). ①에 걸리면 ②·③은 실행되지 않는다.
- ③은 어휘가 겹쳐 ①을 통과한 범위 밖 질문(충수염·이명류)을 자른다. 점수 컷 6의 마진: 거리
  통과 abstain의 최대 점수 4, answerable 최소 8 — 양쪽 2점씩 여유.
- 리랭크는 §28의 규약을 계승한다: 점수 기권도 `retrieval.completed`는 빈 evidence, reason은
  beyond_cutoff와 **같은 문구·같은 사유**(`beyond_cutoff`)로 통합한다 — 사용자에게 「관련
  근거를 찾지 못했다」는 같은 사실이고, 내부 원인 구분은 메트릭 라벨이 아니라 로그로 충분하다.

### 리랭크 실패는 코사인 순위로 폴백한다

LLM 호출이 실패하면(타임아웃·429·파싱 불가) **리랭크 없이 기존 코사인 top-5로 진행**하고
③은 건너뛴다 — 리랭커는 품질 향상 계층이지 가용성 의존성이 아니다. 폴백은
`rag_rerank_total{outcome="fallback"}`으로 센다. 실패가 조용히 상시화되면 지표가 잡는다.

### 리랭커는 LLM 포트를 재사용하지 않는다 — 새 전용 포트다

`LlmProvider.streamAnswer`는 근거 인용 답변 전용 계약이다(§27과 같은 판단). 리랭크는
비스트리밍 단발 호출이므로 `infrastructure/retrieval/reranker.port.ts`(신규)로 감싼다 —
외부 유료 API라 **fake 치환 없이는 e2e 동결이 성립하지 않는다**(§3 포트 기준 충족).
fake는 결정적으로 동작한다(예: 후보 순서 유지 + 고정 점수) — e2e가 게이트·폴백을 검증할
수 있어야 한다.

  실 리랭커로 재실행하면 이 실측이 재현된다. e2e는 fake로 게이트·폴백 동작만 동결한다.

  300자로 상한에 도달했으므로 더 실을 이유가 없다.

## 수용 기준 (= 동결할 e2e 시나리오, Definition of Done)

1. 거리 게이트를 통과한 질문은 리랭커가 반환한 순서의 상위 5개가 `retrieval.completed`
   evidence로 노출된다 (fake 리랭커가 순서를 뒤집으면 뒤집힌 순서가 그대로 반영된다).
2. 리랭커의 top-1 관련도가 점수 컷 미만이면 `answer.abstained`로 끝나고 메시지는 `ABSTAINED`다.
3. 그 기권의 `retrieval.completed`는 빈 evidence를 싣고, reason은 `beyond_cutoff` 문구
   (「질문과 충분히 관련된 지침 근거를 찾지 못했습니다.」)다.
4. 점수 기권은 `rag_abstains_total{reason="beyond_cutoff"}`를 증가시킨다.
5. 거리 게이트(§28)에 걸린 질문은 리랭커가 **호출되지 않는다** (fake 리랭커 호출 기록으로 단언).
6. 리랭커가 오류를 던지면 스트림은 코사인 top-5로 정상 완료되고
   `rag_rerank_total{outcome="fallback"}`이 증가한다.
7. 리랭크로 답한 GenerationRun의 `retrievalPolicyVersion`은 v3 문자열이고, 폴백으로 답한
   경우는 v2 문자열이다.
8. `RETRIEVAL_RERANK_ENABLED=false`면 §28 동작(코사인 top-5 + 거리 게이트)과 동일하다 —
   기존 spec 28 동결 스위트가 이 모드에서 그대로 통과한다.
9. `rerankScoreCutoff`·`rerankCandidates`가 미지정·빈 값이면 코드 기본값(6·30)으로 동작한다.
10. `eval-rag` 리포트에 리랭크 적용 Recall@5·MRR@5와 점수 게이트 포함 기권 지표가 실리고,
    컷·리랭크 미적용 원 순위 지표도 함께 실린다.

## Out of scope

  실측되면 그때 검토한다.
- 리랭크 결과 캐싱, 후보 발췌 길이 튜닝, 점수 컷 자동 조정.
- §28 거리 컷 값 변경 — 이중 게이트에서 각자 역할이 실측으로 확인됐다. 재조정은 운영 분포를
  본 뒤.
- 평가셋 paraphrase 축(축약형 변형) 추가 — 표현 민감성 실증(2026-08-01)의 후속이지만 데이터
  작업이라 별도로 간다.
