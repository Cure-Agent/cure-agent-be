# 31. 하이브리드 검색 — pg_trgm 키워드 arm + RRF 합집합 후보

> **이 문서는 작성 시점의 작업 지시다 — 현재 시스템 상태가 아니다.**

## 목표

§27 판정표의 마지막 발동 항목을 실행한다. 지금의 상한은 후보군이다 — 리랭커는 후보에 있는
정답을 거의 다 올리지만(§29), 벡터 단독 후보군의 Recall@30이 0.968이라 **top-30 밖 6문항은
리랭커가 구제할 수 없다**. 임베딩은 희귀 병명 신호(범불안장애·심장신경증·소음인 망양병)를
일반 임상 어휘가 희석시켜 후보에조차 못 넣는다. 문자 n-gram 키워드 arm을 더해 두 arm의
**합집합**을 후보군으로 열면 후보 커버리지가 1.000이 된다.

## 실측 조사 (2026-08-02, prod ACTIVE 코퍼스 7,154청크 덤프 × 평가셋 answerable 185 / abstain 44)

| 확인 항목 | 실측 |
|---|---|
| 키워드 방식 선정 | **질문 전문 `word_similarity` 채택**: 단독 R@30 **0.978**, top-30 밖 6문항 전부 회수(058→2위·076→3위·079→1위·099→23위·100→17위·154→3위), 전수 스캔 1.1s. 대조군(조사 제거 term별 합산)은 0.941·099/100 미회수·10.8s로 기각. §27 판정표의 문자 n-gram 그대로다 — 어절 경계 공백이 소실된 코퍼스(§19)라 tsvector 어절 매칭이 애초에 불가능하고, trigram은 조사·붙임에 강건하다 |
| 합집합 vs 절단 | RRF(k=60) **top-30 절단은 0.978** — 092·099·100이 잘린다(한쪽 arm 깊은 순위는 절단을 못 넘는다). **합집합 전체(크기 33~60, p50 54)는 1.000** → 절단하지 않고 전부 리랭커에 넘긴다 |
| 전체 파이프라인 (실 리랭커 gpt-5.4-mini, 3단 게이트 동일) | 리랭크 R@5 0.962→**0.973**·MRR@5 0.905→**0.921** (top-30 밖이던 4건이 최종 top-5 진입 — 구조적 개선). 기권 재현율 0.977→**0.955**(실패 1→2건)·과잉 기권 0.016→**0.022**(3→4건) — 양쪽 ±1건은 채점 실행 간 변동 안 |
| 기권 마진 관측 | abstain 8점이 5→**10건** — 어휘 중첩 후보가 늘며 컷 9 바로 아래에 몰린다. 신규 기권 실패 2건은 만성심부전 지침을 9점으로 통과시킨 인접 질문(심근경색·만성신부전). 컷 재조정 판단은 리포트 히스토그램으로(#232 규약) |
| 리랭크 비용·지연 | 후보 p50 54개 → 입력 p50 9.6k 토큰(30개 대비 ×1.7, ≈$0.004/질의), 호출 p50 **1.15s**·p90 1.70s — 30개(0.96s)와 동급 |
| 키워드 arm 지연 | 전수 스캔 1,071ms — 벡터 arm과 **병렬 실행**하면 TTFT 순증 ~0.6s. GiST(gist_trgm_ops)는 빌드 0.9s·KNN 323ms로 실측됐고 값 기준 정확(동점 절단만 다름) — §12 원칙대로 지연이 문제로 관측되면 도입한다 |
| 동점 평원 | `word_similarity` 값 동점이 넓다(한 질문에서 top-30 경계에 72건) — 2차 정렬 키(id)가 없으면 평가가 재현되지 않는다 |

### 구조 — 게이트 3단은 그대로, 후보군만 넓어진다

```
벡터 arm: cosine 오름차순 top-K ────────────┐
                                            ├─ RRF(k=60) 합집합(≤2K, 무절단) → ① 거리 게이트(§28) → ② 리랭크(§29) → ③ 점수 게이트(§29)
키워드 arm: word_similarity(질문, content) 내림차순 top-K ─┘
```

- **arm당 K는 기존 `rerankCandidates`(기본 30)를 재사용한다** — 후보군 크기를 정하는 손잡이가
  둘이 되면 동기화 사고가 난다. RRF의 k=60은 코드 상수다(튜닝은 Out of scope).
- **키워드 arm에 유사도 임계값을 두지 않는다** — 실측 구성 그대로 top-K를 무조건 채운다.
  하위 후보의 노이즈는 리랭커와 ③이 거른다(벡터 arm도 이미 같은 성질이다).
- `word_similarity(질문, content)` **인자 순서를 고정한다** — 이 함수는 비대칭이라(1번 인자의
  트라이그램이 2번 인자의 연속 구간과 얼마나 맞는지) 뒤집으면 다른 값이 된다.
- **융합 정렬은 RRF 점수 내림차순 → 벡터 순위 오름차순(없으면 뒤) → 청크 id 오름차순**이다.
  두 arm에서 같은 순위를 차지한 후보는 RRF 점수가 정확히 같으므로 동점이 흔하다 — 벡터 arm을
  앞에 두는 것은 §28·§29가 그 위에서 정의된 1차 신호이기 때문이고, id는 최종 결정성 보장이다.
- **① 거리 게이트는 후보 최소 코사인 거리로 판정한다** — 벡터 arm top-1과 동치이므로(전 코퍼스
  최소값) §28 의미가 그대로 보존된다. 키워드가 강하게 일치해도 거리 기권이면 기권이다:
  어휘 중첩형 범위 밖 질문은 ③이 잡는 게 §29 실측으로 확인된 역할 분담이다.
- **키워드 arm도 embedding_model·ACTIVE·요청 필터를 동일 적용한다** — 두 arm이 같은 코퍼스를
  본다. 임베딩 모델 교체 시 전건 abstain이 되는 안전성(§14)이 키워드 arm으로 우회되지 않는다.
- 폴백·리랭크 비활성 시 **RRF 순위 top-5**로 진행한다(§29의 「코사인 폴백」 자리를 RRF가
  대체) — no-rerank v4 정책 문자열로 기록돼 리랭크 적용 여부가 구분된다.
- `RETRIEVAL_HYBRID_ENABLED=false`면 §29 동작 그대로다 — 롤백 축.
- **평가도 `hybridEnabled`를 따른다.** 리랭크 선례(§29 rag-eval은 플래그와 무관하게 항상
  잰다)를 여기엔 적용하지 않는다 — 하이브리드는 **리랭커의 입력 순서 자체를 바꾸므로**,
  플래그를 무시하면 검색이 꺼진 배포에서도 리랭크 지표가 융합 순서 기준으로 나와 운영과
  다른 파이프라인을 보고하게 된다. 실제로 §29 기준 10a(순서 유지 fake의 리랭크 MRR =
  원 MRR)가 그 이유로 깨졌다 — 기준 7이 약속한 「§29 동결 스위트 통과」와 정면으로 충돌한다.
  꺼진 상태의 평가는 키워드 arm Recall@K = 0, 합집합 커버리지 = 벡터 Recall@30으로 나온다.

## 수용 기준 (= 동결할 e2e 시나리오, Definition of Done)

1. **후보 확장**: K를 좁혀(`rerankCandidates`) 벡터 arm에 들지 못하지만 질문과 자구가 겹치는
   청크가, 하이브리드 검색 결과에 포함되고 리랭커에도 그 청크가 후보로 전달된다.
2. **arm별 순위 부기**: 결과 각 행은 자신이 속한 arm의 순위를 갖고, 속하지 않은 arm의 순위는
   null이다 (두 arm 모두에 든 행은 양쪽 다 숫자).
3. **거리 게이트 보존**: 후보 최소 코사인 거리가 컷을 넘으면 키워드 일치 청크가 있어도
   기권하고 리랭커는 호출되지 않는다 (§28).
4. **코퍼스 경계**: 키워드 arm은 embedding_model 불일치 청크와 비ACTIVE 판본 청크를 후보에
   넣지 않는다.
5. **요청 필터**: `guidelineIds` 필터가 하이브리드 검색 결과 전체에 적용된다 — 필터 밖 지침의
   청크는 자구가 겹쳐도 후보에 없다.
6. **정책 버전**: 리랭크로 답한 GenerationRun은 v4 rerank 문자열을, 리랭크 실패 폴백은 v4
   no-rerank 문자열을 기록한다. 폴백은 RRF 순위 top-5 근거로 정상 완료되고
   `rag_rerank_total{outcome="fallback"}`이 1 증가한다.
7. **롤백 축**: `hybridEnabled=false`면 검색 결과가 벡터 top-5와 동일하고 정책 문자열은
   §29의 v2/v3다 — spec 29 동결 스위트가 이 모드에서 그대로 통과한다.
8. **기본값**: `RETRIEVAL_HYBRID_ENABLED` 미지정·빈 값이면 코드 기본값(켜짐)으로 동작한다.
9. **관측**: 하이브리드 검색 1회 후 `/metrics`에
   `rag_retrieval_duration_seconds{stage="keyword_search"}` 관측치가 남는다.
10. **평가 지표**: `eval-rag` 리포트에 ⑴ 벡터 원 지표(Recall@5·MRR@5·Recall@30, 기존 값 유지)
    ⑵ 키워드 arm Recall@K ⑶ 합집합 후보 커버리지 ⑷ 하이브리드 리랭크 적용 지표가 모두 실리고,
    실패 문항 표에 arm별 발견 순위가 실린다.

## Out of scope

- **GiST trgm 인덱스** — 실측 완료(323ms)·보류. 코퍼스 증가나 지연 문제가 관측되면 도입.
- RRF k·arm K 튜닝, 가중 융합 — k=60·top-30×2는 실측값이며 튜닝은 측정 루프가 지시할 때.
- 리랭커 개선 — 잔여 실패 5건 중 2건(099·100)은 후보에 있는데 리랭커가 못 올린다(깊은 순위
  인양 실패). 후보군 문제가 아니므로 이 spec 밖이다.
- 점수 컷 재조정 — 8점 몰림(마진 축소)은 관측 항목이지 이번 변경 대상이 아니다(#232 규약).
- 평가셋 확장, FE 표시 변경.
