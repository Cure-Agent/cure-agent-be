# 28. 검색 거리 임계값 — top-1 게이트 기권 연결

> **이 문서는 작성 시점의 작업 지시다 — 현재 시스템 상태가 아니다.**

## 목표

§27이 남긴 첫 개입을 실행한다. 지금 검색은 유사도와 무관하게 top-5를 반환하므로 **범위 밖
질문에도 엉뚱한 근거 5개가 LLM으로 넘어간다** — 근거 0건 기권은 좌표계 불일치·필터 외에는
발화하지 않는다(§27 실측 재확인). top-1 코사인 거리가 임계값을 넘으면 기권하는 게이트를 넣어,
확실히 먼 질문이 그럴듯한 오답 대신 기권을 받게 한다.

## 실측 조사 (2026-08-01, 프로덕션 코퍼스 7,154청크 × 평가셋 74문항 raw 거리)

| 확인 항목 | 실측 |
|---|---|
| **raw 분포는 겹친다** | answerable top-1 max **0.4167** > abstain top-1 min **0.361**. 겹침 구간(0.361~0.4167)에 answerable 5건·abstain 6건 — **완전 분리 컷은 존재하지 않는다** |
| §27 기준선의 갭은 착시였다 | answerable p90(0.357) < abstain p10(0.374)는 양끝 10%를 못 본 것이다. 백분위는 컷 근거로 부족하고 **raw 스윕이 필요했다** |
| **겹침 answerable 5건의 정체** | 전부 **rank 1~2 검색 성공**이다(사상체질 현증·소증, 허실변증설문지, 자폐 변증 등 추상적 진단 질문 — 정답을 1위로 찾고도 절대 거리가 멀다). 이 구간에서 컷은 오답 방지가 아니라 **찾아놓은 정답을 버리는 것**이다 |
| 컷 스윕 | 0.36 → 정답 손실 5/59·기권 재현 15/15 / 0.39 → 3/59·12/15 / **0.42 → 0/59·9/15** |
| per-chunk 필터의 손실 | 유효 컷 구간(0.38~0.40)에서 **top-5에 든 정답 청크 3~4건이 잘린다**(정답 청크 거리 max 0.4171). 게이트는 top-1만 봐야 한다 |
| 기권 경로 현황 | `conversation-stream`의 기권은 `retrieved.length === 0`뿐이고, `retrieval.completed`는 그때 빈 evidence를 싣는다 — 컷 기권도 같은 노출 규약을 따르면 SSE 계약 무변경이다 |
| 기본값 소유 규약 | LLM 튜닝값 선례(#156): 기본값은 코드 DEFAULTS 단독 소유, compose는 `${VAR:-}` 빈 통과만 — 두 곳이 기본값을 가지면 코드 상향이 조용히 무효가 된다 |

### 컷은 0.42다 — 첫 도입은 무후회여야 한다 (2026-08-01 사용자 확정)

0.42는 스윕에서 **정답 손실 0이 증명된 유일한 유효값**이다(기권 재현 9/15 = 60%). 0.39·0.36은
재현을 80~100%로 올리지만 rank-1 정답 3~5건을 기권시킨다 — 범위 밖 차단의 이득은 qa-v3 프롬프트
방어(근거 부족 시 명시, 무관 근거 마커 금지)가 일부 대체하지만, 찾아놓은 정답을 버린 손실은
대체물이 없다. 남은 40%는 다음 스텝(리랭커)의 관련성 점수 위에서 컷을 재설계할 때 줄인다 —
코사인 절대 거리는 질문의 추상도에 끌려가지만 크로스인코더 점수는 관련성 보정이 좋다.

**표본 한계를 명시한다**: answerable max(0.4167)와 컷(0.42)의 여유는 0.0033뿐이고 표본은
59문항이다. 실사용 추상 질문은 컷을 넘을 수 있다 — 그래서 env 조정 가능이 필수이고, 기권
사유가 FE에 전달되어 재질의를 유도한다. 리랭커 후 재측정이 교정 지점이다.

### 게이트는 top-1만 본다 — 통과하면 5건 전부 유지

top-1이 컷 이내면 2~5위에 컷 밖 청크가 있어도 제거하지 않는다. 실측이 근거다: per-chunk
필터는 유효 컷에서 정답 청크 3~4건을 자르고, 노이즈 감소 이득은 추정인데 손실은 실재한다.
컷 하나가 기권 판정과 근거 선별 두 역할을 겸하면 튜닝이 얽힌다 — 근거 선별은 리랭커의 몫이다.

### 판정은 conversation-stream이 소유한다

기권은 대화 정책이지 검색 계층의 것이 아니다. `RetrievalService.search()`는 계속 raw를
반환한다 — §27의 K=30 진단이 **컷 미적용 순위**를 봐야 하고, 평가의 순위 지표와 기권 판정은
다른 축이기 때문이다. 컷 기권 시 `retrieval.completed`는 빈 evidence를 싣는다 — 컷 밖 근거를
노출하면 「근거가 있는데 왜 기권?」이 된다. 근거 0건 경로와 노출 규약이 같아져 SSE 계약도
FE 동작도 변하지 않는다.

## 범위 (진입점)

**신규·변경 엔드포인트 없음. SSE 계약 무변경** — `answer.abstained`·`retrieval.completed`
이벤트 구조 그대로, reason 문구만 사유별로 갈린다.

| 진입점 | 변경 |
|---|---|
| `global/config/retrieval.config.ts` (신규) | `registerAs` + `RETRIEVAL_DISTANCE_CUTOFF` env, 기본값 **0.42는 코드가 단독 소유** (guideline-scan.config 선례) |
| `retrieval.service.ts` | policyVersion을 실사용 컷 포함 **v2**로 범프 — `cosine-top5-cut{컷}-v2/{모델}`. env로 컷을 바꾼 운영 기록도 GenerationRun에서 구분된다 |
| `conversation-stream.service.ts` | top-1 게이트 판정 → 기권 분기. reason: 근거 0건 「검색 조건에 해당하는 지침 근거를 찾지 못했습니다.」 유지 / 컷 「질문과 충분히 관련된 지침 근거를 찾지 못했습니다.」 신설 |
| `metrics.service.ts` | `rag_abstains_total{reason="no_candidates"\|"beyond_cutoff"}` 카운터 신설 — `rag_answers_total`에 라벨을 더하면 answered 시계열까지 빈 라벨이 번지므로 별도 카운터다. abstain 급등 시 「코퍼스 사고인가, 범위 밖 유입인가」가 이 축에서 갈린다 |
| `rag-eval.service.ts` · `rag-eval.report.ts` | 기권 지표 2종 추가 — **기권 재현율**(abstain 문항 중 top-1>컷), **과잉 기권률**(answerable 중 top-1>컷). 리포트 메타에 컷 값 |
| `app.module.ts` | config 등록 |
| `.env.example` · `docker/gcp/compose.yml` | `RETRIEVAL_DISTANCE_CUTOFF` — compose는 `${VAR:-}` 빈 통과만 (#156 규약) |

- **평가의 순위 지표(Recall@5·MRR@5·Recall@30)는 컷 미적용으로 유지한다.** 순위 품질과 기권
  판정을 섞으면 리랭커 전후 비교가 흐려진다 — 컷은 기권 지표 2종에서만 작동한다.
- **e2e 검증 전략**: fake 임베딩의 거리 절대값은 무의미하므로 컷 경계를 실거리로 재현하지
  않는다 — 테스트가 컷을 극단값으로 오버라이드해(0에 가까움 → 전건 기권 / 충분히 큼 → 기권
  없음) **동작만** 검증하고, 좌표계 불일치(§14 legacy-model 기법)로 만든 근거 0건 기권과
  사유가 구분되는지를 본다.

## 수용 기준 (= 동결할 e2e 시나리오, Definition of Done)

1. top-1 거리가 컷을 넘으면 스트림이 `answer.abstained`로 끝나고 메시지 status는 `ABSTAINED`다.
2. 그 기권의 `retrieval.completed` 이벤트는 빈 evidence를 싣는다 — 컷 밖 근거는 노출되지 않는다.
3. top-1이 컷 이내면 top-5 전부가 근거로 유지된다 — 2~5위에 컷 밖 청크가 있어도 제거되지 않는다.
4. 근거 0건 기권은 `rag_abstains_total{reason="no_candidates"}`를, 컷 기권은
   `{reason="beyond_cutoff"}`를 증가시킨다.
5. 두 기권의 `answer.abstained` reason 문구가 사유별로 다르다.
6. 답변이 생성되면 `GenerationRun.retrievalPolicyVersion`에 실사용 컷이 포함된 v2 문자열이
   기록된다.
7. `RETRIEVAL_DISTANCE_CUTOFF`가 미지정이거나 빈 값이면 코드 기본값(0.42)으로 동작한다.
8. `eval-rag` 리포트가 기권 재현율과 과잉 기권률을 포함한다.
9. `eval-rag`의 순위 지표는 컷과 무관하다 — 컷 값을 바꿔도 Recall@5·MRR@5·Recall@30이 불변이다.

## Out of scope

- **per-chunk 필터** — 실측상 유효 컷에서 정답 청크 3~4건을 자른다. 근거 선별은 리랭커의 몫.
- **리랭커** — 다음 스텝. 이 컷은 리랭커 점수 위에서 재설계될 전제의 임시 게이트다(§27 판정표의
  두 발동 항목 중 나머지 하나).
- 컷 자동 튜닝·분포 드리프트 감지 — 운영 데이터(`rag_top1_distance` 히스토그램)가 쌓인 뒤.
- FE 기권 화면·재질의 유도 UI — reason 문구 전달까지가 BE의 몫.
- 임베딩 모델 교체 — §27 판정표에서 발동하지 않았다(Recall@30 = 0.983).
